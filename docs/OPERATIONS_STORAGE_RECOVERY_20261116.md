### Repeat the isolated procedure

1. Verify an owned loopback manifest and create a fresh source test cluster using `scripts/local-system.py --target <base-manifest> --profile test clone-test`. Bootstrap Laravel from the guarded private test profile. Point the local disk at a fresh private source directory. Use synthetic accounts, patients and bytes.
2. Upload through `POST /api/documents`. Record the public document and patient IDs, relative object path, branch, stored length and SHA-256. Create a synthetic encrypted field through an existing Laravel model cast and assert that the raw database value is nonempty ciphertext before backing up.
3. Quiesce writes for a paired database and object snapshot. Use the guarded PostgreSQL dump. Encrypt the object and metadata using a separately generated backup key. Retain the matching application key and any applicable previous keys in private custody. Store decryption material separately from the backup payloads with restricted permissions. This drill used private directories in one container volume. A production recovery plan needs independently protected key custody and encrypted protection for the entire database backup.
4. Restore PostgreSQL into a new cluster using the guarded clone workflow. Use a fresh private storage directory and the preserved test application key. Authenticate the envelope before extracting bytes. Match the document ID, patient ID, branch and relative path to the restored row. Compare exact length and SHA-256 against PostgreSQL before writing to the restored disk. Any mismatch stops recovery.
5. Run the current download route with the authorized and denied actors above. Hash the actual streamed bytes. Separately exercise wrong and missing keys. Keep the source, database and object backups, and private test key custody available for reviewed repeat recovery. Stop the isolated services when finished.

### Limitations

This recovery verifies a paired PostgreSQL snapshot and separately encrypted backup of the existing private-file path. Native application-level document encryption would need a reviewed format, read/write compatibility and migration strategy. Hosted persistent storage, provider encryption, off-site restore, and rollback were outside the tested environment. The download service currently compares file length and does not recompute the stored SHA-256. The recovery procedure therefore checks SHA-256 explicitly before release. Generated billing PDFs and provider-side objects were outside this drill. Previously accepted worker, scheduler, Mailpit, session and local predefense results remain prior evidence. Full application suites, build and predefense were not repeated for this documentation-only local change.
