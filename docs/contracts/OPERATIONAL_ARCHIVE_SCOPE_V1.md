# Operational archive scope v1 — approved A1–A4

Implemented locally, not deployed/integrated. Approval source: project-owner Batch11 instructions, November15,2026. Original GEN-11 in `FINALS-QA-REVISIONS.md` requests soft archival with actor/time/role, role-filtered archives, server enforcement, notification archival and broad Owner restore/permanent removal. A1/A3/A4 retain the stricter private-record and no-hard-delete boundaries; this is **partial original GEN-11**, not universal archive closure.

| Resource | Read / archive authority | Scope and evidence | Restore / permanent deletion |
| --- | --- | --- | --- |
| Personal notifications | Exact authenticated recipient, including Owner for their own account only | Existing `GET /api/notifications?collection=active|archived&before=<public cursor>`; recipient-scoped cursor,50 rows and accurate unread metadata. `POST /api/notifications/{id}/archive` is monotonic, repeat-safe, audited and returns exact immutable archive receipt. Read/read-all preserve recipient authority. Another recipient's ID404, including when the caller is Owner. Archive records retain actor/time; immutable audit retains event actor role. | No supported route; disabled/unavailable in UI. No retention invented. |

Cursor resolution now uses the same filter set; unknown/out-of-filter cursor yields an empty page, preserving the established unknown-cursor contract. Existing archive viewing does not confer restoration or active-care status. | Remain unavailable absent an explicit entity-specific contract/policy. No hard delete authorized. |

Audit date filters now bind explicit Asia/Manila offset-bearing instants: inclusive local-day start, exclusive next-day start. This corrects a reproduced midnight defect where generic datetime binding dropped the offset and hid early-morning records. Timestamp storage, original event dates and the retained column's whole-second precision are unchanged. One bounded regression covers the last stored second before the day, exact midnight, last stored second of the day and exact next midnight.

Actual failures retain existing401/403, invalid filters422 `{message,errors}`, recipient/cursor404 and archive capability503 behavior. No new archive endpoint or privilege is inferred from a component being visible. Owner Staff-roster actions are additionally discoverable through existing audit Operational activity filters; branch filters and stale-response protections remain.

Original broad “Dr Dana sees all” cannot be interpreted as access to private recipient or clinical contents. Owner restore/permanent-removal and universal entity archive coverage remain outside this implemented scope under A3/A4. A future change requires an entity-specific permitted transition and privacy contract; these approved secure defaults do not authorize it now.
